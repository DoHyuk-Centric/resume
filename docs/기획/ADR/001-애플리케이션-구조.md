# ADR-001: Next.js와 NestJS를 분리한 모듈형 모놀리스

- 상태: 채택
- 날짜: 2026-07-22

## 상황

제품은 단순한 정적 이력서를 넘어 인증, 콘텐츠 재사용, 문서 조립, 템플릿 버전, 파일 업로드와 향후 PDF 작업을 제공한다. Next.js만으로 구현할 수 있지만 비즈니스 규칙과 권한이 프론트엔드 프로젝트에 혼재할 가능성이 있다.

## 결정

- 웹은 Next.js App Router로 구현한다.
- API는 NestJS로 구현한다.
- PostgreSQL에는 NestJS만 직접 접근한다.
- 초기 백엔드는 마이크로서비스가 아닌 모듈형 모놀리스로 구성한다.
- FE·BE는 한 모노레포에서 관리한다.
- OpenAPI로 API 계약과 프론트 타입을 연결한다.

## 결과

### 장점

- 비즈니스 로직과 권한 경계가 명확하다.
- NestJS 모듈, Guard, DTO와 테스트 구조를 활용할 수 있다.
- 향후 다른 클라이언트가 API를 재사용할 수 있다.
- PDF 작업과 파일 처리 확장이 쉽다.

### 단점

- 두 애플리케이션을 실행하고 배포해야 한다.
- FE·BE 간 네트워크와 계약 관리가 필요하다.
- CORS와 쿠키 정책을 별도로 설계해야 한다.
- 단일 개발자에게 초기 설정 부담이 늘어난다.

## 대안

- Next.js Route Handler만 사용: 개발 속도는 빠르지만 장기적인 도메인 경계가 약해진다.
- 마이크로서비스: 현재 규모에 비해 운영 비용과 장애 지점이 과도하다.
