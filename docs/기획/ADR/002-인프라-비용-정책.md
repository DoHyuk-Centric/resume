# ADR-002: AWS 중심 유료 인프라와 초기 단일 서버

- 상태: 채택
- 날짜: 2026-07-22

## 상황

Supabase 무료 사용량을 모두 사용했으며 외부 서비스에 추가 비용을 분산하고 싶지 않다. MVP는 사용자와 트래픽이 검증되지 않았으므로 관리형 서비스를 모두 도입하면 고정 비용이 커진다.

## 결정

- 유료 인프라 비용은 AWS에만 지출한다.
- Next.js는 개인·비상업 MVP 동안 Vercel Hobby 무료 범위에 배포한다.
- NestJS와 PostgreSQL은 초기 AWS Lightsail 2GB 단일 서버에서 실행한다.
- 사용자 파일과 DB 백업은 S3에 저장한다.
- 상업화 또는 Vercel 무료 조건 이탈 시 프론트엔드도 AWS로 이전한다.

## 결과

### 장점

- 초기 고정 비용이 낮고 예측 가능하다.
- 유료 청구와 운영 자원을 AWS에 집중할 수 있다.
- 제품 검증 후 DB와 Worker를 점진적으로 분리할 수 있다.

### 단점

- 단일 서버 장애로 API와 DB가 동시에 중단된다.
- PostgreSQL 패치, 백업과 복구를 직접 운영한다.
- 2GB 메모리에서 API와 DB의 자원 경합 가능성이 있다.
- Vercel Hobby는 상업 용도로 사용할 수 없다.

## 위험 완화

- PostgreSQL 포트를 외부에 공개하지 않는다.
- 매일 S3 외부 백업을 수행한다.
- 복원 절차를 작성하고 정기적으로 테스트한다.
- AWS Budget, 디스크, CPU, 메모리와 Health 알림을 설정한다.
- 서버 PDF 생성은 별도 Worker로 분리하기 전에는 도입하지 않는다.

## 대안

- Lightsail Managed Database: 운영 부담은 낮지만 초기 월 고정 비용이 증가한다.
- RDS: 확장성과 관리 기능이 좋지만 MVP에는 비용과 구성이 무겁다.
- 외부 PaaS: 빠르지만 유료 비용을 AWS에 집중한다는 정책과 맞지 않는다.
