# Resume Studio 기획

> 문서 상태: 초안  
> 최종 갱신: 2026-07-22

## 1. 문서 목적

이 문서는 Resume Studio의 문제 정의, 제품 목표, MVP 범위와 주요 기술 결정을 요약하는 문서 허브다. 구현 세부사항과 기술별 위험·대안·트레이드오프는 아래의 연결 문서에서 관리한다.

## 2. 문제 정의

이력서와 포트폴리오를 웹으로 만들면 디자인 자유도는 높지만, 지원 기업마다 내용을 수정하고 프로젝트·기술·자기소개를 반복해서 배치하기 어렵다. 반대로 문서형 도구는 수정은 편하지만 인쇄 품질, 표현력과 커스텀 레이아웃에 제약이 있다.

Resume Studio는 이 문제를 다음 방식으로 해결한다.

1. 경력, 프로젝트, 기술, 문제 해결 사례와 자기소개를 콘텐츠 보관함에 한 번 저장한다.
2. 지원 기업과 직무에 맞는 콘텐츠만 선택한다.
3. 선택한 콘텐츠의 순서를 조정하고 문서별 표현을 덮어쓴다.
4. 템플릿을 적용해 웹 문서와 PDF로 출력한다.

핵심 가치는 **예쁜 템플릿 제공**보다 **하나의 경험 저장소에서 지원처별 문서를 재조립하는 것**에 둔다.

## 3. 대상 사용자

### 1차 사용자

- 프로젝트 중심으로 역량을 설명하는 개발자
- 기업마다 이력서와 포트폴리오 내용을 바꾸는 취업 준비생
- 웹 포트폴리오와 PDF 이력서를 함께 관리하려는 사용자

### 후속 확장 대상

- 디자이너, 기획자, 마케터 등 포트폴리오가 필요한 직군
- 반복적으로 제안서와 경력기술서를 제작하는 프리랜서

MVP에서는 범용 직군을 지원하지 않고 개발자 문서 작성 경험에 집중한다.

## 4. 제품 원칙

1. **Content First**: 콘텐츠와 표현을 분리한다.
2. **재사용 가능성**: 동일 콘텐츠를 여러 문서에서 선택해 사용한다.
3. **명시적 연결**: 템플릿은 DB 테이블이 아닌 공통 문서 스키마를 소비한다.
4. **출력 안정성**: 화면뿐 아니라 A4 인쇄 결과를 제품 품질로 취급한다.
5. **점진적 확장**: 자유 배치 에디터보다 검증된 블록과 템플릿을 먼저 제공한다.
6. **비용 통제**: 유료 인프라 비용은 AWS에만 지출한다.

## 5. MVP 범위

### 포함

- 회원가입, 로그인, 로그아웃
- 프로필·경력·프로젝트·기술·문제 해결 사례 CRUD
- 콘텐츠 보관함
- 지원용 문서 생성·수정·삭제
- 문서에 콘텐츠 추가·제거·순서 변경
- 문서별 콘텐츠 문구 덮어쓰기
- 섹션 숨김과 페이지 나누기
- 제공 템플릿 2개
- 텍스트·이미지 기반 사용자 정의 페이지
- 실시간 미리보기
- 인쇄용 CSS와 브라우저 PDF 저장
- 자동 저장
- 공개 여부 설정

### 후순위

- 완전한 자유 배치 템플릿 제작기
- 템플릿 마켓
- 사용자 간 공동 편집
- AI 문장 작성 및 채용 공고 분석
- 임의 HTML·JavaScript 삽입
- 서버 기반 PDF 생성
- 범용 직군 템플릿
- 모바일 애플리케이션

## 6. 사용자 핵심 흐름

```text
회원가입/로그인
  → 콘텐츠 등록
  → 지원용 문서 생성
  → 콘텐츠 선택
  → 순서 및 문구 조정
  → 템플릿 선택
  → 미리보기
  → 웹 공유 또는 PDF 저장
```

## 7. 시스템 개요

```text
사용자
  ↓
Vercel: Next.js Web
  ↓ HTTPS
AWS Lightsail: NestJS API
  ├─ PostgreSQL
  └─ AWS S3
       ├─ 사용자 이미지
       ├─ 생성 PDF
       └─ DB 백업
```

- 프론트엔드: Next.js App Router + TypeScript
- 백엔드: NestJS + TypeScript
- 데이터베이스: PostgreSQL
- 파일 저장: AWS S3
- 프론트엔드 배포: Vercel Hobby의 무료 범위
- 유료 지출: AWS로 제한
- 저장소: FE와 BE를 포함하는 모노레포

## 9. 성공 기준

MVP는 사용자가 아래 작업을 완료할 수 있을 때 제품 가설을 검증할 수 있다.

- 콘텐츠를 한 번 저장하고 두 개 이상의 문서에서 재사용한다.
- 지원 기업별로 프로젝트와 기술 구성을 다르게 만든다.
- 코드를 수정하지 않고 문서의 내용과 순서를 변경한다.
- 웹 미리보기와 A4 PDF 결과가 일관되게 출력된다.
- 저장한 문서를 다시 열었을 때 내용과 배치가 유지된다.

## 10. 주요 위험

| 위험 | 영향 | 초기 대응 |
|---|---|---|
| 기능 범위가 템플릿 편집기로 확장됨 | MVP 지연 | 제공 블록과 템플릿으로 제한 |
| A4 페이지 나눔이 콘텐츠 길이에 따라 깨짐 | 출력 품질 저하 | Print CSS 및 Playwright 시각 테스트 |
| 단일 서버 장애 | API와 DB 동시 중단 | S3 외부 백업과 복구 절차 |
| FE·BE 타입 불일치 | 런타임 오류 | OpenAPI 타입 생성과 CI Type Check |
| 사용자 파일 업로드 악용 | 비용·보안 문제 | 크기·형식 제한과 Presigned URL |
| Vercel Hobby의 비상업 조건 | 서비스 공개 제약 | 상업화 전에 AWS 배포로 이전 |

## 11. 미결정 사항

- ORM: Drizzle과 Prisma 중 선택
- 인증: NestJS 자체 세션/토큰과 AWS Cognito 중 선택
- 문서가 원본 콘텐츠 변경을 즉시 반영할지, 생성 시점을 스냅샷으로 보존할지
- 이미지 파일별 최대 크기와 사용자별 저장 한도
- 공개 문서 URL 정책과 검색 엔진 노출 정책
- 템플릿 스키마 및 허용 블록의 최종 규격
- 모노레포 패키지 관리자와 빌드 도구

결정이 완료되면 관련 기술 문서와 ADR에 근거를 추가한다.
