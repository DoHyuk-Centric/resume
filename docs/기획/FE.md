# 프론트엔드 기획

> 문서 상태: 초안  
> 담당 영역: `apps/web`

## 1. 목표

Next.js 기반으로 콘텐츠 관리, 문서 조립, 템플릿 미리보기와 인쇄 경험을 제공한다. 프론트엔드는 DB에 직접 접근하지 않으며 모든 영속 데이터와 권한 검사를 NestJS API를 통해 처리한다.

## 2. 기술 구성

- Next.js App Router
- React
- TypeScript strict mode
- CSS 기반 화면·인쇄 스타일
- NestJS OpenAPI에서 생성한 API 타입
- Playwright E2E 및 시각 회귀 테스트

상태 관리와 폼 라이브러리는 실제 화면 복잡도를 확인한 뒤 결정한다. 서버 상태와 에디터 로컬 상태를 하나의 전역 저장소에 섞지 않는다.

## 3. 주요 화면

```text
/
/login
/signup
/dashboard
/contents
/contents/projects
/contents/experiences
/contents/skills
/documents
/documents/new
/documents/[documentId]/edit
/documents/[documentId]/preview
/templates
```

## 4. 에디터 구성

```text
좌측: 콘텐츠와 블록 목록
중앙: 문서 구조 및 순서 편집
우측: A4 미리보기
```

초기 에디터가 지원하는 블록:

- 프로필
- 경력 목록
- 프로젝트 목록
- 기술 목록
- 문제 해결 사례
- 자유 텍스트
- 이미지
- 1열·2열 컨테이너
- 페이지 나누기

임의 HTML 및 JavaScript는 보안과 출력 안정성을 위해 허용하지 않는다.

## 5. 데이터 처리 원칙

- API 응답 타입을 프론트에서 수동으로 중복 선언하지 않는다.
- NestJS Swagger/OpenAPI 문서에서 TypeScript 타입을 생성한다.
- 사용자 입력은 클라이언트에서 1차 검증하되 서버 검증을 대체하지 않는다.
- 저장 중, 저장 완료, 실패 상태를 사용자에게 명확히 표시한다.
- 낙관적 업데이트는 되돌리기가 안전한 작업에만 사용한다.

## 6. 자동 저장

### 제안 흐름

```text
사용자 입력
  → 로컬 상태 즉시 반영
  → 짧은 debounce
  → API 저장
  → 저장 버전 갱신
```

### 예상 문제

- 여러 탭에서 같은 문서를 수정할 때 마지막 저장이 앞선 변경을 덮어쓸 수 있다.
- 네트워크 실패 후 사용자가 저장됐다고 오해할 수 있다.
- 블록 순서 변경 요청이 연속으로 발생할 수 있다.

### 대응

- 문서 `version` 또는 `updatedAt` 기반 충돌 감지
- 저장 실패 상태와 재시도 버튼 제공
- 순서 전체를 한 트랜잭션으로 저장
- 브라우저 이탈 전 미저장 변경 경고

## 7. 웹 미리보기와 PDF

MVP는 `window.print()`와 Print CSS를 사용한다. 버튼은 브라우저 인쇄 창을 열며 파일을 자동 저장하지 않는다.

필수 Print CSS 항목:

- `@page` A4 크기와 여백
- 배경색 및 이미지 출력
- 블록 내부 페이지 분리 방지
- 명시적 페이지 나누기
- 링크 및 편집 UI 숨김
- 폰트 로딩 완료 후 출력

서버 기반 PDF 생성은 후순위로 두고, 필요해지면 별도 Worker에서 Playwright/Chromium을 실행한다.

## 8. 접근성과 반응형

- 모든 입력에 연결된 label 제공
- 키보드로 블록 선택과 이동 가능
- 드래그 앤 드롭 외에 이동 버튼 제공
- 색상만으로 저장·오류 상태를 표시하지 않음
- 모바일에서는 편집기보다 조회와 간단 수정에 우선순위
- 미리보기 확대·축소가 문서 실제 크기를 변경하지 않게 구현

## 9. 예상 문제와 트레이드오프

| 항목 | 선택 | 이점 | 비용/위험 |
|---|---|---|---|
| Next.js와 Nest 분리 | 프론트는 API만 호출 | 책임과 권한 경계 명확 | 네트워크·계약 관리 필요 |
| 실시간 미리보기 | 상태 변경 즉시 렌더링 | 작성 경험 개선 | 긴 문서에서 렌더링 비용 증가 |
| 블록 기반 편집 | 정해진 블록 조합 | 구현·출력 안정성 | 자유 배치 제한 |
| 브라우저 PDF | Print CSS 사용 | 서버 비용 없음 | 브라우저별 출력 차이 |

## 10. 테스트 범위

- 컴포넌트 단위 테스트: 입력, 오류, 블록 UI
- API 타입 검사: 생성된 OpenAPI 타입 최신 상태 확인
- Playwright: 로그인부터 문서 출력까지 핵심 흐름
- 시각 테스트: 템플릿 및 Print CSS 스크린샷 비교
- 반응형 테스트: Chromium 데스크톱, 모바일 Chrome, 모바일 Safari

상세 흐름은 [자동화 문서](./자동화.md)를 따른다.

## 11. 미결정 사항

- 폼 라이브러리
- 서버 상태 캐시 도구
- 블록 정렬 라이브러리
- 디자인 시스템 및 컴포넌트 정책
- 폰트 제공 방식과 라이선스
