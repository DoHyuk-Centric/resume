## 1. 주요 업무

인프런 서비스의 핵심인 프론트엔드 시스템 개발 업무를 담당합니다.
TypeScript / React / Next.js 기반의 웹 프론트엔드와 React Native 기반의 모바일 앱을 빠르고 안정적으로 구축하며, 기술적 완성도뿐 아니라 비즈니스 임팩트와 사용자 경험을 함께 고민하는 프론트엔드 엔지니어를 찾습니다.

- TypeScript, React, Next.js(Pages Router) 기반으로 인프런 서비스의 웹 프론트엔드를 개발하고 배포합니다.
- React Native 기반으로 인프런 Android/iOS 모바일 앱을 개발하고 배포합니다.
- pnpm + Turborepo 모노레포 환경에서 웹과 모바일이 함께 사용하는 공용 패키지와 서비스 코드를 관리합니다.
- Module Federation(Micro Frontend)을 활용해 독립적으로 개발·배포 가능한 프론트엔드 아키텍처를 운영합니다.
- TanStack Query를 활용한 서버 상태 관리와 SSR/CSR을 상황에 맞게 적절히 선택하여 최적의 사용자 경험을 제공합니다.
- 상황에 맞게 네이티브 구현과 WebView 구현을 적절히 나눠 진행합니다.
- Mantine 기반 자체 디자인 시스템을 활용해 일관된 UI를 구현하고, 재사용 가능한 컴포넌트를 개발합니다.
- Mixpanel, GTM 등을 활용한 사용자 행동 분석과 Hackle을 통한 A/B 테스트로 데이터 기반의 제품 개선에 참여합니다.
- i18next, locize를 활용해 한국어, 영어, 일본어, 베트남어 등 다국어 서비스를 지원합니다.
- Datadog을 통해 웹/모바일 에러 추적, 페이지 로드 시간, API 응답 속도 등을 실시간으로 모니터링하며 성능 병목 지점을 발견하고 개선합니다.
- 코드리뷰(온라인 PR, 오프라인 페어프로그래밍)를 통해 함께 성장하는 문화를 만들어 갑니다.

## 4. 함께하고 싶은 팀원상 (인재상)

### 4-1. 소통과 투명성

- 작업 진행 상황, 이슈, 완료 예정일을 먼저 공유하여 동료(PM, BE, PD)가 다음 단계를 예측할 수 있게 만드시는 분
- "안 돼요"가 아니라, 어떤 시도를 했고 원인이 무엇인지 맥락을 함께 전달해주시는 분
- 타 직군에게 기술적 제약을 설명할 때, 그들의 언어로 이해하기 쉽게 풀어서 이야기하시는 분
- 문서화(기능명세서, 운영 매뉴얼, 인수인계 문서 등)를 통해 지식을 팀에 공유하시는 분

### 4-2. 말보다 시각화로 증명하는 태도

- 아이디어 제안 시 빠르게 프로토타입을 만들어 눈으로 보여주시는 분
- 기술 도입 전 POC(Proof of Concept)를 통해 검증한 뒤 팀에 제안하시는 분
- 본인이 만든 서비스를 실제 운영까지 해보신 분

### 4-3. 비즈니스 임팩트를 우선하는 관점

- "왜 이 기능을 만드는가?"를 먼저 묻고, 기획 의도에 맞춰 기술적 대안을 제시하시는 분
- 화려한 기술 스택보다 서비스의 안정성과 사용자 편의를 최우선으로 두시는 분
- 기획서를 보고 기술적으로 문제가 될 부분을 미리 파악해 공유하시는 분
- 사용자 행동 데이터를 기반으로 제품 개선에 참여하신 경험이 있으신 분

### 4-4. 팀의 짐을 덜어주는 완결성

- 테스트코드 작성, Storybook 문서화 등 자체 검증 체계를 갖추고 계신 분
- 팀의 비효율(반복 작업, 문서화 부재)을 스스로 찾아 개선하고 자동화해본 경험이 있으신 분
- 디자인 시스템, UI 라이브러리 구축 등 팀 전체의 생산성 향상에 기여해본 경험이 있으신 분
- 웹 서비스 성능 개선(Lighthouse, code splitting, 번들 최적화 등)을 진행해본 경험이 있으신 분
- Datadog 등 모니터링 도구를 활용해 에러를 추적하고 장애를 해결해본 경험이 있으신 분
- 동일 장애 재발 방지를 위해 시스템/프로세스 개선을 해보신 분

## 5. 인프랩 개발팀의 미션과 가치

> 출처: https://tech.inflab.com/20231117-devteam-value/

### 5-1. 미션

> 프로덕트 엔지니어로서 내/외부 고객의 신뢰를 얻기 위해 **적절한 시기에 적합한 도구로 고객의 문제를 해결**한다.

핵심은 "적절한 시기". 모든 문제를 즉시 해결해야 하는 것은 아니며, 각 상황에 맞는 최적의 도구를 선택하는 것이 중요하다는 관점.

### 5-2. 추구하는 4가지 가치

| 가치 | 설명 |
|---|---|
| 존중 | 팀원들을 전문가로서 진심 어린 마음으로 대한다. 무례함은 취향이 아니다. |
| 탁월성 | 평범함에 안주하지 않고 높은 기준의 성과를 추구한다. |
| 신뢰 | 내/외부 고객뿐 아니라 팀원들 간의 건강한 신뢰 관계를 구축한다. |
| 실행 | 완벽하지 않은 계획이라도 즉시 실행하고 진행 중에 수정한다. |

### 5-3. 일하는 방법 (8가지)

1. **상대 인정** — 채용된 모든 팀원은 검증된 전문가임을 전제로 대화한다.
2. **신뢰 구축** — 함께 실행하며 전략을 수정할 수 있는 관계를 형성한다.
3. **전염시키기** — 계몽이 아닌 모범으로 긍정적 영향력을 발휘한다.
4. **사실 기반 보고** — 추측이 아닌 검증된 정보만 공유한다.
5. **감정 분리** — 개인 기분이 태도가 되지 않도록 관리한다.
6. **역할 초월** — 문제가 보이면 책임 구분 없이 먼저 해결한다.
7. **적정 해결법** — 기술 검토 후 필요한 방법만 선택한다.
8. **전문성과 생산성** — 기술 숙련도를 높여 효율성을 향상시킨다.

## 6. 공고 핵심 키워드 요약 (지원서 작성 시 참고)

- **기술 스택**: TypeScript, React, Next.js(Pages Router), React Native, pnpm + Turborepo 모노레포, Module Federation(Micro Frontend), TanStack Query, Mantine 디자인 시스템, i18next/locize, Mixpanel/GTM/Hackle, Datadog
- **신입 관점 포인트**: 경력·학력 무관. 우대사항에서도 "몰라도 빠르게 내 것으로 만드는 학습법"을 명시 → 스택 나열보다 **학습 과정·문제 해결 과정**을 보여주는 것이 중요
- **반복 강조되는 태도**:
  - 문서화 선호 ("대화보다 하나의 문서를 작성하고 공유")
  - 비개발자의 언어로 소통 (공고 우대사항과 인재상에 모두 등장)
  - 프로토타입/POC로 눈에 보이게 증명
  - "왜 만드는가"를 먼저 묻는 비즈니스 관점
  - 데이터(사용자 행동, 모니터링) 기반 개선
  - 실제 운영 경험, 장애 대응과 재발 방지
