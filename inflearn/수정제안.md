**위치·방식**: 팀원 4인 역할 분담 그리드 **전체를 비우고 그 자리를 Git Flow 전략으로 교체**.

- **삭제 범위**: 도입 문장 "4인 팀에서 역할이 어떻게 나뉘었고, 무엇을 근거로 기록했는지를 정리했습니다."(line 1347~1350) + 김도혁/박소유/이동근/임태형 4인 카드 그리드(line 1352~1385)
- **삭제 근거**: 팀원별 역할·기여도는 이미 슬라이드 하단 "참고자료(원본 PDF)"의 팀원 기여도·팀 활동 보고서 링크로 증빙되고, 04번 슬라이드에 본인 역할이 명시돼 있어 중복. 반면 Git Flow는 자격요건인데 문서 표면에 0회 노출 — 지면 교환 가치가 명확함.

**교체안** (기존 pf-card 그리드 자리에, 도입 문장 + Git Flow 블록):

도입 문장 교체:

```
브랜치 전략과 코드 리뷰 규칙으로 4인의 코드가 어떻게 안전하게 합쳐졌는지를 정리했습니다.
```

본문 블록 (h3 "브랜치 전략 · 코드 리뷰 (Git Flow)"):

```
- main / develop / release / feature / fix / hotfix 6종 브랜치로 운영하고,
  모든 병합은 본인 외 1명 이상 Approve를 받은 PR로만 진행했습니다.
- 커밋은 <type>: <설명> 컨벤션(7타입)으로 통일해 6주간 1,191개를 기록했습니다.
- 3단계 점진 배포(6/22 · 7/1 · 7/6)로 릴리스했고, 결제 웹훅·Storage 트래픽
  이슈는 hotfix 브랜치로 실서비스 중 대응했습니다.
```

시각 자료(권장): 텍스트만 두면 슬라이드가 허전해질 수 있으므로, ① GitHub Network(브랜치) 그래프 스크린샷 또는 ② main←release←develop←feature 흐름 다이어그램 1장을 곁들일 것. "말보다 시각화" 인재상과도 맞음.

> 포인트: "Git Flow를 안다"가 아니라 **release·hotfix까지 실제로 굴렸다**는 사실이 핵심. 핫픽스 2건은 인재상 "완결성"(장애 대응)의 이중 근거이므로 반드시 포함.
> 주의: 역할 그리드를 지우면 "무엇을 근거로 기록했는지"라는 기존 도입 문장이 참조하던 대상이 사라지므로, 하단 "주간 보고서 운영" 단락의 기여도 산정 서술(최초 작성자·코드 계보·PR 근거)은 그대로 유지해 역할 증빙 기능을 넘겨받게 할 것.

### 2-3. portfolio.html · 03번 슬라이드 Kanto 카드 (line 604) — [해결: 근거 확인됨, 유지 + 강화]

**Kanto 저장소 확인 결과 WCAG 문구는 과장이 아님.** 커밋 `5e09252`(PR #169) "WCAG 2.1 AA 기준 접근성 전면 개선"이 실재: aria-label 18개 파일, aria-expanded/haspopup/pressed, role="tab/tablist/tabpanel", `<time dateTime>`, `<dl>/<dt>/<dd>` 구조화, 헤딩 계층 정리, div onClick→`<Link>`·img onClick→`<button>` 키보드 접근성 확보. 별도로 `cec93e3`에서 모달 role="dialog"·aria-modal·Escape 닫기·포커스 관리.

**결정**: 문구 삭제가 아니라 **유지**. 오히려 6장(접근성 표면화)에서 구체 근거로 승격할 것. 면접 답변 카드: "18개 파일 전반의 아이콘 버튼 aria-label, 탭 UI role 시맨틱, 키보드 접근 불가였던 div/img 클릭 요소를 Link/button으로 교체" — 커밋 단위로 답변 가능.

> 기존 진단("표에 스택만 있고 담당 불명")은 오판 — 본인 담당 확정. 인프런은 i18next·locize로 한/영/일/베 4개 언어를 운영하므로, 도구만 다를 뿐 같은 문제(번역 키 관리, 날짜·숫자 로캘, 누락 검출)를 풀어본 경험으로 제시 가능.

### 7-1. resume.html · Kanto 담당 줄 (line 122~123)

**위치**: 담당 목록에 다국어 병기 (3-1의 공지사항 추가와 함께 반영).

**수정 후 예시**: `내 프로필, 이용약관·약관 다국어(EN/FIL), 공지사항(모바일 반응형·국제화), 실시간 1:1 채팅(Supabase Realtime), AI 챗봇(멀티 LLM 폴백), …`

> 담당 줄이 길어지면 "다국어(next-intl, EN/FIL) 적용" 을 별도 불릿로 빼는 것도 방법.

### 7-2. portfolio.html · 04번 또는 05번 슬라이드

**위치(권장)**: 04번 슬라이드 "핵심 기능" 목록(line 858~878)에 항목 1개 추가, 또는 05번 경험 슬라이드에 한 줄.

**추가안**: `다국어 지원 - next-intl 기반 EN/FIL 국제화 (약관·공지·날짜 로캘 처리, 번역 API 장애 시에도 저장되는 폴백 설계)`

> 자소서 연결: 인프런 주요업무 "i18next, locize를 활용해 한국어, 영어, 일본어, 베트남어 등 다국어 서비스를 지원합니다"에 1:1 대응하는 유일한 경험이므로 자소서 소재로도 확보.
