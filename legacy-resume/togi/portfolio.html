문서 자동화

AI 기반 취합·요약을 위해 문서의 분류, 파일명, 작성 순서를 표준화하고 팀의 작업 기록에 적용했습니다.

  • 문서화 구현 당시의 문제 인식·판단 과정·설계 의도를 이력으로 남겨, 이후 다른 팀원이 작업 배경을 파악하고 후속 개발에 참고할 수 있도록 기록
  • 자동화 상세한 작업 기록에 드는 시간을 줄이기 위해 팀원들과 필수 항목·작성 규칙을 합의하고, AI로 초안을 구조화·정리해 문서 작성 시간을 단축

Notion CMS 기반 이용약관

배포 없이 수정하고, 캐시로 빠르게 조회

약관 수정마다 코드를 다시 배포하지 않도록 Notion을 CMS로 활용하고, 반복 조회로 느려진 탭 전환은 클라이언트 캐시로 개선했습니다.

반응형 UI 모바일은 현재 약관 중심의 드롭다운, 데스크탑은 가로 탭으로 구성하고 탭이 넘치면 좌우 이동 버튼과 페이드 표시
공통 컴포넌트 TermsHeader·TermsNav·TermsContent로 헤더·탐색·본문을 분리해 약관 종류별 동일한 UI 재사용
Notion CMS 운영자가 Notion에서 약관을 수정하면 서비스가 최신 콘텐츠를 조회하도록 코드와 콘텐츠 관리 영역 분리
약관 라우트
통합 운영정책·서비스 등 6개의 개별 페이지를 /terms/[type] 동적 라우트로 통합하고, URL의 type을 Notion 페이지 ID에 매핑해 중복 코드 제거
문제 해결
  • 문제약관 탭을 전환할 때마다 Notion API를 다시 호출해 콘텐츠 표시가 늦어지고 사용 흐름이 끊김
  • 해결약관 종류·언어를 키로 응답과 저장 시각을 브라우저 로컬 저장소에 보관하고 10시간 TTL 이내에는 캐시 우선 사용
  • 결과캐시가 없거나 만료된 경우에만 GET 요청과 로딩 UI를 실행해 탭 이동·새로고침 시 반복 요청 제거

신뢰 수치화 & 채팅 운영

KTS·KPPS 신뢰도 시스템

거래 상대방의 신뢰도와 인기 게시물을 객관적으로 판단할 기준이 필요했습니다.

이에 거래·리뷰·활동·신고 데이터를 KTS로, 게시물 반응·최신성·작성자 신뢰도를 KPPS로 산정해 프로필 신뢰도와 인기 게시물 노출에 반영했습니다.

점수 시각화
  • KTS를 1.2초 카운트업 애니메이션과 등급별 색상으로 표현
  • 거래·리뷰·활동·신고 데이터의 가중치로 산정된 A–E 신뢰 등급 표시
인기 게시물
  • 작성자의 신뢰도 점수는 게시물의 인기 점수에 직접적 영향
  • 위험 등급 작성자의 게시물은 인기 목록에서 제외
인기 배지 연동
  • DB 컬럼 is_popular 값에 따라 방렌트·중고거래 카드에 인기 배지를 조건부 렌더링
  • KTS와 KPPS의 연계 결과를 게시물 카드에서 즉시 식별하도록 시각화
  • RPC Server Action에서 KTS 계산 후 KPPS를 순차 재계산해 최신 점수 반영

실시간 채팅·운영 로그

거래 전 사용자의 상호작용을 위해서 실시간 소통 수단이 필요했습니다.

이에 사용자 간 원활한 거래를 위해 1:1 실시간 채팅을 구현했습니다. 또한 신고·분쟁 발생 가능성을 고려해 관리자가 대화 내역을 확인하고 대응할 수 있는 운영 도구도 함께 구축했습니다.

실시간 수신 Supabase Realtime 기반 사용자 간 실시간 1:1 채팅 구현

전송 경험 읽음 상태 동기화와 낙관적 업데이트로 즉각적인 메시지 전송 경험 제공

  • ReactMarkdown을 메시지를 주고받기도 전에 무조건 불러오고 있었습니다. 실제로 필요한 시점에만 불러오도록 지연 로딩으로 바꾸고, 상호작용이 없는 화면은 서버에서만 처리하도록 분리해 첫 화면이 뜨는 속도를 끌어올렸습니다.

메시지 리스트 리렌더링 최적화 - memo

채팅이 길어질수록 새 메시지 하나가 추가될 때마다 이전 메시지까지 화면 전체가 다시 그려지는 문제를 발견했습니다.

  • 메시지가 쌓일수록 새 메시지 하나가 추가될 때마다 이전 메시지까지 전부 다시 그려지고 있었습니다
  • 원인은 리액트의 기본 동작 방식을 고려하지 못한 제 실수였습니다.
    상태가 하나 바뀌면 화면에 그려진 자식 컴포넌트를 전부 다시 그린다는 것을 알게 되었습니다.
  • MessageItem을 별도 컴포넌트로 분리하고 memo를 적용했습니다. 새 메시지가 추가돼도 기존 메시지들은 자신의 props가 그대로면 리렌더링을 건너뛰고, 새로 추가된 메시지만 실제로 다시 그려집니다. 이를 토대로 대화가 길어져도 체감 성능이 개선되었습니다.

Firebase → Supabase, 인증 공급자 일원화

인증 공급자 분리로 드러난 수정·삭제 권한 문제 해결

Supabase에서 데이터를 관리하면서 Firebase로 사용자를 인증해 게시글 수정·삭제 시 작성자를 구분하기 어려운 문제를 발견했습니다. 서로 다른 UID를 직접 연동하기 어렵다고 판단해 인증 수단을 Supabase로 옮겼습니다.

검토했지만 기각한 방안

  • UID 매핑 DB · Firebase UID와 Supabase ID를 중간 테이블에 저장 → 두 시스템을 경유하고 결합 관계가 느슨해짐
  • JWT 로컬 세션 저장 · 웹을 미들웨어처럼 사용 → 클라이언트 보관에 따른 보안 부담과 쿠키 제한 환경을 고려

최종 선택 - 공급자 일원화

  • Firebase 로그인을 포기하고 Supabase Auth로 인증 수단 교체
  • onAuthStateChanged를 Supabase의 onAuthStateChange로 변경
  • DB·Storage·Auth를 Supabase SDK 한 곳에서 관리
문제 게시글을 작성자가 아닌 사용자도 수정·삭제할 수 있는 소유권 검증 허점 발견

웹 접근성 - 시맨틱 구조와 ARIA

스크린리더와 키보드로도 동일하게 열리는 메뉴

Tab으로 메뉴 항목을 순차 이동하고 Enter로 접근할 수 있도록 키보드 흐름을 구현했습니다. 시맨틱 마크업과 ARIA 상태를 연결하고, 메뉴가 열리고 닫힐 때 포커스를 이동·복원하도록 개선했습니다.

상황

메뉴가 div 중심으로 구성되어 스크린리더가 상태를 읽지 못하고 키보드만으로 조작할 수 없었습니다.

과제

마우스 없이도 메뉴를 탐색·선택하고, 열린 상태와 현재 포커스를 보조기기에 전달해야 했습니다.

행동

시맨틱 태그와 ARIA를 적용하고 Tab·Enter·Escape, 포커스 이동·복원 로직을 구현했습니다.

결과

키보드만으로 메뉴를 열고 이동·선택·닫을 수 있으며, 스크린리더가 메뉴 상태를 인식하게 됐습니다.
