## A. resume.html

### A-1. 소개 섹션 전면 교체
- **전**: "React·Next.js 기반으로 팀 1개·개인 3개 완성 …" + "AI 도구를 역할별로 분리 운용해 팀의 개발 기간을 단축" (수치 근거 없는 효과 서술)
- **후**: "프론트엔드에 뿌리를 두고 팀의 구조를 세우는 개발자입니다"를 헤드라인으로, ① 정체성 ② 팀 구조/컨벤션/일정 운영 ③ 실측 성과(8.2배·84%·83%) + "프론트엔드 밖 경계도 넘는다"의 3단 구성.
- **근거/의도**: 과장 표현(개발 기간 단축) 제거 → 검증 가능한 실측 수치로 대체. 인재상 "시각화로 증명"·"완결성"과 정렬.

### A-2. Kanto 역할 줄에 "Git Flow 전략 설계" 추가
- **후**: 역할 = "서비스 구조 설계와 데이터 연동, **Git Flow 전략 설계**, 실시간 채팅·인증 보안, 관리자 시스템, 팀 주간 보고서와 일정 운영"
- **근거**: 본인이 브랜치 전략을 설계했음을 확인. 자격요건 "Git Flow를 이해하고 계신 분" 대응. 면접에서 설계 근거(release/hotfix 분리 이유 등) 소유권 검증에 답변 가능해야 함.

### A-3. Kanto에 Git Flow 운용 불릿 추가
- **후**: "Git Flow(6종 브랜치)·PR 승인 규칙 기반 협업 설계·운용, 3단계 점진 배포·hotfix 2건 실서비스 대응"
- **근거**: Kanto 저장소 README + 커밋 1,191개 + hotfix 2건(결제 웹훅·Storage 트래픽). A-2의 "설계" 주장을 운용 사실로 뒷받침. hotfix는 인재상 "완결성"(장애 대응) 이중 근거.
- **비고**: 한 줄 넘침 방지를 위해 구분자를 ` — `→`, `, `, `→`·`로 압축.

### A-4. Kanto 담당 줄에 공지사항(반응형)·다국어 추가
- **후**: 담당 = "내 프로필, **이용약관·약관 다국어(EN/FIL)**, **공지사항(모바일 반응형·국제화)**, 실시간 1:1 채팅 …"

### A-5. ESLint-KR 문구 정확화 + 역량 중심 재작성
- **"기여" 표현 수정**: "한국 개발자 커뮤니티에 **기여**하고자" → "한국어 실전 가이드를 **직접 만들어 공개**하고자" (오픈소스 기여 오해 제거).

- **근거**: 동기는 상위 불릿과 중복이고 공고 역량과 무관. 우대사항 "재사용 가능한 컴포넌트"에 대응. (당초 추가하려던 스모크 테스트 줄은 D 참고 — 최종 제외)

### A-6. 레이아웃 간격 조정 (넘침 방지)

## B. portfolio.html

### B-1. 08번 "협업 방식" — 팀원 역할 그리드 → Git Flow 블록 교체
- **삭제**: "4인 팀에서 역할이 어떻게 나뉘었고 …" 도입문 + 김도혁/박소유/이동근/임태형 4인 카드 그리드.
- **추가**: "브랜치 전략 · 코드 리뷰 (Git Flow)" 소제목 + 브랜치 병합 흐름 시각화(feature·fix·hotfix → develop → release → main(배포)) + 불릿 3개(6종 브랜치·PR 승인 규칙 / 커밋 컨벤션 7타입·1,191개 / 3단계 점진 배포·hotfix 2건).
- **근거**: 자격요건 Git Flow 표면화. 역할 증빙은 하단 "주간 보고서 운영"(최초 작성자·코드 계보·PR 근거)과 참고자료 PDF가 대체하므로 정보 손실 없음. 이력서 A-2/A-3의 시각 증거 역할.
- **⚠️ 확인 필요**: 그리드보다 세로 높이가 커져 A4 슬라이드 넘침 가능성 → 인쇄 미리보기 확인. 넘치면 WBS 섹션 상단 여백(mt-8→mt-6) 또는 불릿 축약으로 조정.

### B-2. 06번 프로필 문제해결 — 소개 모순 해결 + 접근성 근거 추가
- **모순 해결**: "**팀 컨벤션에 따라** 페이지 전체를 서버 컴포넌트로 두고" → "이 문제를 계기로 '데이터 조회는 서버 컴포넌트, 인터랙션만 클라이언트' 원칙을 **직접 제안해 팀 컨벤션으로 정했고**". 이력서 소개(A-1)의 "원칙을 정해 팀 컨벤션으로 만들었고"와 일치시킴.
- **접근성 불릿 추가**: "같은 리팩터링에서 접근성도 함께 개선 — heading 계층 정리, 탈퇴 모달 role=dialog·Escape·포커스 관리, 탭 role=tablist·aria-selected".
- **근거**: 커밋 `cec93e3`("프로필 페이지 로직 hook 분리 및 접근성 개선")이 서버 컴포넌트 리팩터와 접근성을 실제로 함께 처리 → 서사가 정확.

### B-3. 03번 Kanto 타임라인 카드 — 접근성·다국어 명시
- **후**: "공통 디자인 시스템 구축 (WCAG 2.1 AA)" → "공통 디자인 시스템·WCAG 2.1 AA 접근성 구축" + "next-intl 기반 다국어(EN·FIL) 지원" 불릿 신설.

### B-4. 04번 Kanto 핵심 기능 — 다국어 항목 추가
